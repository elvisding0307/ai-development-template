## macOS 原生流程

使用实际 Tauri WebView、Rust IPC 和 SQLite，调试客户端将数据隔离在 `/tmp/qinghe-native-qa`。未向正常应用数据库写入演示记录。

| 操作 | 实际观察 |
|---|---|
| 新建图书 | 馆藏 QA001、《人间草木》及中文作者／分类／位置保存后出现在列表，初始为可借 |
| 新建读者 | QR001 测试读者保存成功，详情在借数量为 0 |
| 从读者档案进入借书 | 工作台预选该读者，选择 QA001 后显示借期及应还日期 |
| 确认借出 | Rust 返回成功，读者在借数变为 1，实体书从可借候选移除，记录应还日期为 2026-11-30 |
| 查询及归还 | 借阅记录显示在借，点击归还进入确认；完成后显示实际归还时间，待还列表为空 |
| 创建备份 | 原生保存对话框导出独立 SQLite 文件；完整性检查为 ok，包含当时的未还借阅 |
| 恢复文件选择与校验 | 原生打开对话框选择备份，显示图书／读者／借阅／未还计数；未勾选确认前恢复按钮不可用 |
| 覆盖恢复 | 恢复后未还数量从 0 回到备份中的 1；显示独立安全备份路径；馆藏页重新显示借出状态 |
| 正式版启动 | 最终 release `.app` 原生启动成功，使用系统应用数据目录，Schema 1，馆藏／读者／借阅均为空，未混入隔离验证数据 |
| 关闭重启 | 同一隔离目录重开后，馆藏、中文资料及恢复后的借出状态仍存在 |
| 异常数据库启动 | 损坏的隔离数据库触发原生中文错误对话框，包含数据路径和保留安全备份提示；确认后以失败状态退出，不开放业务操作 |

页面布局还通过框架阶段的 Playwright 1280 × 800 检查，实际原生借阅表格也已目视检查。自动化交互测试使用模拟 IPC，未将其当作原生系统对话框验证。
