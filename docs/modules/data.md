# 数据管理模块

项目见[项目概览](../project.md)，全局约束见[整体架构](../architecture.md)。

## 职责与边界

将当前全部业务数据导出为可恢复备份，并用经过校验的备份替换当前数据。首版只有手动备份和完整恢复，不提供合并、云端存储或定时备份。

## 对外能力与功能

| 能力 | 功能规格 | 状态 |
|---|---|---|
| 完整备份、校验、确认恢复 | [数据备份与恢复](../features/data/backup-restore.md) | 已实现 |

## 核心业务规则

- 备份包含馆藏、读者、全部借阅记录及数据版本，采用包含应用标识和模式版本的单个 SQLite 快照文件。文件包含读者联系方式，导出时提示其为本地明文备份。
- 备份与恢复期间阻止新的业务操作，等待已开始的事务完成后再操作；互斥同一时间只能执行一次。
- 恢复为完整替换，必须先校验并展示备份摘要，再由管理员明确确认；取消选择或确认不修改当前数据。
- 恢复前在应用数据目录生成当前数据的一致性安全备份。若无法生成，停止恢复。每次恢复使用独立文件名，不覆盖此前安全备份；成功提示路径，首版不自动清理。
- 首版仅接受相同模式版本、正确应用标识且通过完整性、外键及业务一致性检查的备份；较旧／较新版本拒绝并说明版本不兼容，不隐式迁移或清空数据。
- 恢复失败保留当前有效数据；恢复中途崩溃也须在下次启动恢复到替换前或完整替换后的状态，禁止打开半恢复数据继续写入。

## 依赖与接口约束

| 依赖或调用方 | 协作内容 | 接口与行为约束 |
|---|---|---|
| [馆藏](catalog.md)、[读者](readers.md)、[借阅](circulation.md) | 完整数据快照和一致性恢复 | 不挑选部分业务表恢复，成功后所有界面重新读取 |
| Tauri 原生文件对话框 | 选择导出或恢复文件 | 取消为正常退出；禁止将当前数据库或其辅助文件作为备份目标或恢复来源 |
| SQLite / rusqlite | 快照、验证与恢复 | 使用[一致性备份 API](https://docs.rs/rusqlite/latest/rusqlite/backup/index.html)，不直接复制运行中的数据库主文件 |

恢复方案必须满足上述失败与崩溃不变式，具体文件替换与回滚实现由代码及集成测试验证，不在此预写内部实现。
