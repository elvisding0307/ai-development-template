# 借书登记

- 所属模块：[借阅](../../modules/circulation.md)
- 状态：已实现
- 技术验证：本模块已通过 `npm run build`、`npm test`（9 条借阅界面模拟 IPC 测试，另含 2 条框架测试）、`cargo test --manifest-path src-tauri/Cargo.toml`（9 条借阅测试，另含 2 条框架测试）及严格 Clippy 检查。覆盖事务回滚、并发唯一性／名额、日期边界、历史快照、归还幂等、组合查询、同一目标的重复导航，以及结果数量减少后的分页回退。当前为模块 worktree 验证，尚待主分支集成与原生桌面验证。
- 业务验收：待人工验收；借期及数量上限采用首版基线。

## 用途与目标

管理员在借还工作台选择一位读者与一本实体书，确认后一次完成借出登记，保持借阅与馆藏状态一致。

## 输入与输出

| 项目 | 内容 | 约束 |
|---|---|---|
| 输入 | 启用读者 ID、实体书 ID | 必须存在；一次一本；可从档案页面预选，最终均须重新校验 |
| 输出 | 借阅记录、借出时间、应还日期及成功／失败反馈 | 后端生成时间、日期和记录 ID，前端不提交可借结论或当前在借数量 |

借期、上限、逾期提示及历史快照遵守[借阅公共规则](../../modules/circulation.md#核心业务规则)，其中借期与上限采用首版基线。

## 行为

1. 进入借书页签，按读者编号／姓名搜索选择启用读者，显示当前在借数量和逾期提示；同名候选显示编号。
2. 按馆藏编号／书名搜索可借图书，候选显示馆藏编号，避免同书多副本混淆。
3. 确认区域显示读者、实体书及预计应还日期。提交时后端重新检查存在性、启用状态、唯一在借关系与读者名额。
4. 所有校验通过后，在同一事务内新增借阅并保存借出时资料快照；成功显示实际借出时间和应还日期。若跨午夜使应还日期不同，以成功结果为准。
5. 成功后刷新图书状态与读者在借数量，清空图书选择，保留读者以便继续登记；提交期间禁用按钮。

## 边界与异常

| 情况 | 预期处理 | 可观察结果 |
|---|---|---|
| 未选择读者或图书 | 拒绝提交 | 指出缺失项目 |
| 读者已停用或达到上限 | 拒绝借出 | 说明原因，无新借阅 |
| 图书已借出或停用 | 拒绝借出并刷新候选 | 原借阅不变，不占用读者名额 |
| 读者存在逾期但未达上限 | 显示提示后仍可办理 | 按公共规则成功借出，不计罚款 |
| 重复点击或并发提交 | 事务与约束复核 | 同一图书最多一条有效借阅，失败提交无部分写入 |
| 数据库失败或维护中 | 拒绝或回滚 | 显示失败原因，保留当前选择，不显示借出成功 |

## 验收标准

| 编号 | 给定条件 | 操作或事件 | 预期结果 |
|---|---|---|---|
| AC-01 | 启用读者无在借书，图书可借 | 提交借出 | 新增一条未归还记录，图书显示借出，在借数量为 1 |
| AC-02 | 系统本地日期为 2026-10-31 | 成功借出 | 应还日期为 2026-11-30；时间由后端生成 |
| AC-03 | 读者已有 5 本未还 | 借另一本 | 被拒绝，原 5 条借阅及目标图书状态不变 |
| AC-04 | 读者已有 4 本未还 | 同时提交两本不同图书 | 至多一笔成功，总在借数量不超过 5 |
| AC-05 | 可借图书一册 | 对同册重复／并发提交 | 仅产生一条未归还记录 |
| AC-06 | 选择完成后读者被停用或图书已借出 | 再提交 | 后端拒绝过期选择，不产生新记录 |
| AC-07 | 读者有逾期但在借数量小于上限 | 借可借图书 | 显示逾期提示，仍可成功办理 |
| AC-08 | 借出事务提交失败 | 重新查询馆藏和读者 | 无新增借阅，图书仍可借，在借数量不增加 |
